AccessGuard checks whether your API enforces the read-access rules you declare. A first scan of your own test environment takes about 15 minutes to set up.

  1. Run the demo. Open the demo project on your overview page and start its scan. It shows a full report with findings, evidence and fix guidance, then lets you “deploy” a fix and retest.
  2. Prepare test data. In your test environment, create at least two tenants (customer organisations) with one user per role, and a few records per tenant. Give protected fields distinctive values (for example TEST-ACME-INVOICE-0001) so their presence in a response is unambiguous.
  3. Create a project. Enter the base URL, the allowed path prefixes, how users authenticate and an endpoint that returns the signed-in user. Optionally import endpoints from your OpenAPI document.
  4. Declare users and rules. Add the test users, the records with their owners and who may read each record.
  5. Install a runner next to your test environment and give it the test users' credentials locally (runner guide).
  6. Review and start the scan. Approve the scope, follow the progress and read the report.
  7. Fix and retest. Each finding has fix guidance and a retest button. A finding is resolved as verified only when its retest passes.
